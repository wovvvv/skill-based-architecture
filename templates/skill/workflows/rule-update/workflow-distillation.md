# Workflow Distillation

Use this owner only after Task Closure reports `Closure Complete`, presents one evidence-backed workflow proposal, and the user accepts it. That acceptance starts the described maintenance task without another start confirmation. Before a persistent change or no-write decision, consume [`workflows/update-rules.md` § Shared Durable-Write Contract](../update-rules.md#shared-durable-write-contract) once.

## Accepted Workflow-Distillation Input

Acceptance bypasses only the ordinary Recording Threshold and redundant upgrade-Plan approval. Reconstruct the accepted contract from at least two independently completed semantic instances:

- reusable goal;
- ordered stage relations;
- inputs and outputs;
- integrated acceptance;
- authority checkpoints;
- runtime parameters;
- only evidence-proven conditional branches.

Retries or repeated substeps inside one unfinished delivery count once. Match semantic identity rather than command, tool, path, or temporal adjacency.

Inspect existing owners and return exactly one result:

1. **`extend`** - the owner of the same result/acceptance lacks a stage, parameter, branch, authority check, proof, route, or local action hook.
2. **`compose`** - complete owners already express the sequence. With no durable route, hook, state, authorization, or integrated-acceptance gap, make no workflow change.
3. **`create`** - no owner has the independently reusable goal, cross-step decisions/state, authority checkpoints, and integrated acceptance. Create one complete orchestration owner; consumers retain only evidence-required trigger, participation, and acceptance hooks.

## Canonical Provenance and Consumption

Resolve provenance before mutation: the canonical owner may be downstream-owned, meta-generated, or package/market-maintained. Edit only that owner, use the repository-owned assembly/install path, and verify every affected downstream consumer and harness surface. A source-only change without required downstream consumption is incomplete; generated or installed copies are never independent owners.

For cross-repository orchestration, keep one complete owner for ordered stages, shared decisions/state, authority checkpoints, and integrated acceptance. Local repositories keep only the trigger, participation, and local acceptance needed to act without exploratory navigation.

If canonical-source mutation or required assembly crosses current authority, return `requires-user-authority` without mutation. Workflow acceptance never grants commit, push, MR, deploy, publish, database, work-item, version-revision, reviewer selection, merge, tenant/session, team promotion, or other external/shared-system authority.

## Workflow-Specific Completion

- [ ] Two independent completed semantic instances support one accepted reusable contract.
- [ ] Exactly one `extend`, pure `compose`, or `create` result was returned; pure composition created no wrapper.
- [ ] One canonical owner contains the complete procedure and consumers retain thin local hooks.
- [ ] Assembly/install used the owned path and every affected downstream/harness consumer was verified.
- [ ] No repository delivery, platform, database, promotion, or shared-system authority expanded.
