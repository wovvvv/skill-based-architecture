# Workflow Distillation Proposal

Load this protocol only after `Closure Complete` when a plausible repeated-procedure signal already exists, and present the completion report first. Evidence normalization may start earlier, but blocked, paused, stopped, or unverified work produces no proactive proposal.

## Evidence

Require two independently completed instances with the same reusable goal, ordered stage relations, inputs/outputs, integrated acceptance, and authority checkpoints. They may occur in the same Session or across tasks/Sessions. Retries or repeated substeps inside one unfinished result count once; frequency, adjacency, and command similarity do not qualify. Use only current/relevant history and the smallest targeted retrieval needed to prove or falsify the second instance; create no signature store, ledger, counter, timeline, route, or placeholder.

Keep variable values as parameters and admit a conditional branch only when its applicability is proven. Inspect existing owners and choose one result:

- `extend`: an owner of the same reusable result is incomplete;
- `compose`: complete owners already combine without a durable route, hook, state, authority, or integrated-acceptance owner; present no proposal;
- `create`: an independently reusable cross-step contract has no owner.

For `extend` or `create`, present concrete repeat evidence, compact goal/flow, one recommendation, canonical-owner-to-downstream path, material parameters/branches/authority boundaries, and one consent question. Decline/defer creates no durable record and suppresses the same proposal for the Session until stronger evidence or explicit reopening.

Acceptance starts a newly routed task through [`workflow-distillation.md` § Accepted Workflow-Distillation Input](../workflows/rule-update/workflow-distillation.md#accepted-workflow-distillation-input) without redundant reconfirmation. It grants no commit, push, MR, deploy, publish, database, work-item, version, reviewer, merge, or other external authority.
