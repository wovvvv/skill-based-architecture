# Plan And Knowledge Closure

Load this protocol only for Design-derived, business-bearing, knowledge-changing, or Composite Plan work. It returns reconciliation evidence to `task-closure.md`; it cannot declare readiness or completion.

## Reconciliation

1. For Composite work, read every Component from its canonical owner. Reject missing, `abandoned`, unresolved-Delta, superseded-but-consumed, or unfinished required inputs; reconcile affected Components before integrated acceptance.
2. Replay each relevant user-confirmed Decision Context. For business-bearing work, read the routed business rule and compare `desired business truth` with code/tests/runtime `current implementation fact`. Material drift returns to [`user-decision-drift.md`](user-decision-drift.md); Closure never resolves it.
3. Reconcile later Decision Deltas across the governing Plan, Component interfaces, Task Anchor, implementation evidence, tests, and business owner. Preserve authority and mark replaced meaning explicitly.
4. Run Plan Leaf Reconciliation: write confirmed durable business meaning through the Business Truth owner, preserve Requirement Provenance to the source Plan, and verify the normal activation path changes a future action.
5. Run Knowledge Reciprocity for changed rules, Gotchas, references, or workflows: integrate/correct/retire the existing concept, prove owner and activation, and avoid transcript copies or parallel truth.
6. Calibrate `distilled_to:` to current live semantic destinations. Do not list generated consumers, implementation-only files, rejected candidates, or nonexistent targets.

## Return

Return exactly one result: `pass` with owner/proof paths; `return` with the Task Execution or Rule Update action still required; or `blocked` with the missing authority/Component. Abandoning an Integrating Plan never changes independent Component state.

Rationalization to reject: “I can mention mainline drift in the final report.” First disclosure at Closure is too late; return to the drift owner immediately.
