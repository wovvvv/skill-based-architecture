# Change Contract Protocol

Use this after workflow selection only when missing semantic evidence could change scope, desired-meaning authority, preserved behavior, or acceptance. This file owns the complete translation and implementation-binding state; it is not a task route, business model, question script, source-search procedure, Task Anchor, or persistent artifact.

## Activation And Fast Path
- Reuse a clear request, confirmed Plan, observed/expected contract, or already proven owner when it satisfies the applicable readiness checks; PRD/Figma presence, keywords, task size, or complexity never activate this protocol alone.
- Keep one evolving runtime Change Contract: `semantic-incomplete -> semantic-ready -> localization-required/owner-proven -> binding-incomplete -> implementation-ready`, with return states below.

## Semantic Intent
- Record only activated dimensions: desired observable outcome; actor/trigger when material; authoritative requirement/constraint versus proposed/context/excluded input; scope; preserved behavior/non-goals; proof direction; normative and technical unknowns.
- Every material requirement-bearing input receives an evidenced disposition; inference may generate candidates but cannot create authority or associatively expand behavior.
- `semantic-ready` means the intent can constrain localization and reject a false owner, with no user-owned meaning, permission, scope, preservation, or acceptance choice capable of redirecting it.
- Agent-discoverable files, symbols, callers, state/config owners, paths, and implementation facts remain technical unknowns and enter [`source-localization.md`](source-localization.md); ask one minimum question through [`ambiguous-request-gate.md`](ambiguous-request-gate.md) only for a remaining normative blocker.

## Implementation Binding
- Give source localization the desired outcome, material surface, authority/exclusions, preserved behavior, candidate region/vocabulary, technical unknowns, and candidate-falsification evidence; consume its proven owner, current behavior, change point, affected path, contradictions, and residual uncertainty.
- Treat ordinary Current/Target difference as the change to bind. Source evidence returns to semantic interpretation only when it invalidates meaning, authority, scope, object relationship, preservation, or proof.
- `implementation-ready` requires still-valid Semantic Intent, proven canonical owner/source relationship, bound Current -> Target, closed decision-bearing path and activated high-cost contract/permission/data/transaction/compatibility/migration/failure boundaries, plus fitted proof.
- A final file list, line-level design, exhaustive call graph, helper names, and written tests are not prerequisites. Admit later files only through a proven producer/consumer/state/contract/generation edge and update impact/proof before mutation continues.
- Evidence inside the bound contract updates it; evidence changing owner, scope, a high-cost boundary, or acceptance returns to localization/translation; conflict with user-confirmed meaning invokes [`task-execution.md` § User Decision Drift Gate](../workflows/task-execution.md#user-decision-drift-gate).

## Consumers And Lifetime
- Task workflows repeat only their trigger, provided input, consumed output, and current-task acceptance. Task Execution derives Goal/Done When/Boundaries after binding; Closure reconciles the final expanded implementation and proof against this contract.
- Keep the contract in current Session/native Plan/Task Anchor state and internal by default. Surface a compact hard-gate/review/audit checkpoint only when needed; ordinary tasks create no contract file, ledger, Wiki, manifest, index, database, or generated state.
